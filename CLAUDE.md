# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This is the **Koraki fork** of [PathOfBuildingCommunity/PathOfBuilding-PoE2](https://github.com/PathOfBuildingCommunity/PathOfBuilding-PoE2), an offline Path of Exile 2 build planner. Upstream is a **LuaJIT application** whose UI/OS integration comes from a native "graphics host" called **SimpleGraphic** (shipped only as Windows binaries under `runtime/`).

The fork's purpose: add a **native-Linux web client** (`web/`) that drives the **unmodified** PoB2 calculation engine headlessly, with no Wine. The hard constraint below makes the difference between this fork and upstream maintainable.

### THE core constraint: never modify `src/`

All custom code lives in `web/`. The engine in `src/` (and `runtime/`, `spec/`) is treated as a vendored upstream and is kept **byte-for-byte identical** so that `git merge upstream/dev` stays conflict-free (upstream ships engine fixes, data-mined content, and patch notes weekly via `.github/workflows/upstream-sync.yml`). If you need an engine behavior change, do it from `web/` — override globals in `web/server.lua` *after* `dofile("HeadlessWrapper.lua")`, as is already done for `Deflate`/`Inflate`. See `docs/syncing-upstream.md` and `web/PLAN.md` §1 ("Locked decisions").

The only files outside `web/` that are fork-additive (safe to edit): `docs/syncing-upstream.md`, `REPO_REVIEW.md`, `.github/workflows/upstream-sync.yml`, and this file.

## Commands

Everything runs under **LuaJIT** natively on Linux — no Wine needed for the engine or tests.

```bash
# Run the web client (PoC): boots the engine as a localhost HTTP service + opens browser UI
./web/run.sh                       # serves http://127.0.0.1:8088 (POB_PORT to change)
# Share build files with a desktop/Wine install:
export POB_BUILD_DIR="$HOME/.wine/drive_c/users/$USER/AppData/Roaming/Path of Building (PoE2)/Builds"

# Run the engine headless (REPL/scripting; exposes globals build, newBuild(), loadBuildFromXML)
cd src && LUA_PATH='../runtime/lua/?.lua;../runtime/lua/?/init.lua;;' luajit HeadlessWrapper.lua

# Tests (busted specs in spec/System/*_spec.lua, run via HeadlessWrapper under LuaJIT)
busted --lua=luajit                # all tests, from repo root (config in .busted)
busted --lua=luajit spec/System/TestSkills_spec.lua   # a single spec file
docker compose up                  # tests in the canonical CI container (pinned tool versions)
```

Dependencies for the above: `luajit` plus LuaRocks modules `luautf8`, `busted`. The
web app (`web/`) needs `lua-zlib` (Deflate/Inflate) + Node 20; it is fully containerised
(`web/Dockerfile` bundles all of them) and run via `web/run.sh` — no native toolchain.

Notes:
- `.busted` excludes the `builds` tag by default and sets `helper = HeadlessWrapper.lua`, `directory = src`, `ROOT = ../spec`.
- There is one **pre-existing** test failure on `dev` (`TestSkills_spec.lua` "Keeps Virtuous armour scaling during Full DPS loop") — it is not introduced by fork work.
- `tests/` (Python) only covers the `fix_ascendancy_positions.py` helper script, unrelated to the engine.

## Architecture

### Engine (`src/`) — upstream, read-only
- **Boot:** native GUI loads `src/Launch.lua` (host injects rendering/input/fs/network globals); `src/Modules/Main.lua` registers two modes — `LIST` (`BuildList.lua`, build picker) and `BUILD` (`Build.lua`, the planner). Immediate-mode: the whole screen redraws every frame.
- **Headless boot:** `src/HeadlessWrapper.lua` is a pure-Lua stub of the SimpleGraphic host. It boots the full engine with no graphics and exports globals `build`, `mainObject`, `newBuild`, `loadBuildFromXML`. `Deflate`/`Inflate` are **stubbed to ""** here (build-code import/export needs them wired — `web/server.lua` does this via lua-zlib).
- **Calc engine** (`src/Modules/Calc*.lua`): `CalcSetup` assembles actor mod databases (passives, items, jewels, auras, config); `CalcPerform`/`CalcOffence`/`CalcDefence` compute DPS/EHP. Largest hot path.
- **Mod system** (`ModParser.lua`, `ModDB.lua`, `ModList.lua`, `ModStore.lua`): parses natural-language modifiers into structured mods, cached in a generated `src/Data/ModCache.lua`.
- **Data** (`src/Data/`, `src/TreeData/`): generated game data (passive trees per game version, uniques, bases, gems, stat descriptions). Files headed `-- This file is automatically generated, do not edit!` come from `src/Export/` (Windows-oriented GGPK tooling). These dominate the line count.
- See `docs/rundown.md` for a file-by-file tour and `REPO_REVIEW.md` for the architecture deep-dive and Linux-support analysis.

### Web client (`web/`) — the fork's work
A three-tier web app driving the unmodified engine headlessly (see `web/PLAN.md` for
the spec, `web/README.md` for orientation, `web/PARITY.md` for the §5 sign-off, and
`web/DEPLOYMENT.md` to run it). **Everything is containerised** — the host needs only
Docker; the image bundles Node + LuaJIT + lua-zlib/luautf8.

- `web/engine/` — **LuaJIT engine kernel**: `kernel.lua` speaks newline-delimited
  JSON-RPC over stdio (no sockets), boots via `dofile("HeadlessWrapper.lua")`, wires
  real zlib `Deflate`/`Inflate`, and routes to `api/{build,character,config,calcs,notes,
  skills,items,tree}.lua` which call the same logic methods the desktop UI/specs use.
  `serialize.lua` projects engine objects to JSON DTOs (preserving `^`-colour escapes).
  `print` is rerouted to stderr so stdout stays a clean protocol stream.
- `web/server/` — **Node/TS gateway**: spawns/supervises the kernel (auto-restart),
  brokers WebSocket ⇄ JSON-RPC, serves the SPA, and runs **build-keyed shared sessions**
  (broadcast `build.updated` to all subscribers, debounced autosave to the shared
  `Builds/` XML, late-join rehydrate) for cross-device continuity.
- `web/app/` — **React+TS+Vite SPA**: PoE2 design system + tabs (Build/Tree/Skills/
  Items/Calcs/Config/Notes), Build Manager, PixiJS passive tree, command palette.
- `web/shared/` — TypeScript RPC + DTO contract (the transport-agnostic seam).
- `web/parity/` — the numeric-parity corpus + runner (the §8 gate).
- `web/poc/` — the original Lua HTTP PoC, archived for reference.

Commands (all via Docker):
```bash
web/run.sh            # build + start the LAN service (docker compose up -d) on :7632
web/run.sh dev        # gateway (tsx watch) + Vite HMR
web/run.sh test       # app Vitest + server Vitest (incl. parity) + upstream busted
```
The engine in `src/` stays byte-for-byte identical; engine behaviour changes are made
from `web/engine` only (override after `dofile("HeadlessWrapper.lua")`).

## Conventions

- **Lua style** (`.editorconfig`): tab indentation, max line length 120, trailing whitespace preserved.
- Build share/import codes are `base64url(zlib-compressed XML)` — that's why `Deflate`/`Inflate` matter for any code-level interop.
- PRs to upstream target the `dev` branch. This fork's default branch is also `dev`.
